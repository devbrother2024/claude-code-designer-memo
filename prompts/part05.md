# Part 5. AI 친화적인 Figma 시안 설계

## P5-1 | 실습: 구현하면 깨질 곳 찾아 고치기

먼저 Figma에서 `연습/규칙 위반` 프레임을 보고 개발자가 AI로 구현하면 깨질 곳(좌표와 빈 상자, 카드 위에 올려 둔 글자, 값으로 넣은 색, 줄 높이 Auto 제목, 손으로 그린 버튼, 자동 이름)을 찾는다. 고칠 때 Claude를 쓰려면:

```
이 프레임을 개발자가 AI로 구현해도 깨지지 않게 고쳐줘: {내 복제본의 연습/규칙 위반 프레임 링크}

- 좌표로 놓인 요소와 간격용 빈 상자는 오토레이아웃의 padding과 gap으로
- 카드 위에 올려 둔 글자는 카드 안으로, 메모 줄과 버튼은 파일의 컴포넌트로
- 값으로 들어간 색과 글자는 파일의 변수와 텍스트 스타일로
- `Frame`, `Group`으로 시작하는 이름은 역할 이름으로

고친 항목을 목록으로 알려줘.
```

## P5-2 | 선택 실습: 같은 화면, 다른 구조 구현해 비교하기

여유가 있는 사람만 한다. 시작 시안의 `홈_최종_v2`는 `완성 예시/Home`과 겉모습이 같고 구조만 다르다(수업에서 본 실험과 같은 시안). 두 프레임을 서로 다른 대화에서 따로 구현한다.

```
이 Figma 프레임을 HTML 파일 하나로 구현해줘: {완성 예시/Home 프레임 링크}
- compare 폴더에 a.html로 만들어
- 시안과 최대한 똑같이, 모바일 폭 기준
```

`/clear`로 새 대화를 열고 입력한다.

```
이 Figma 프레임을 HTML 파일 하나로 구현해줘: {홈_최종_v2 프레임 링크}
- compare 폴더에 b.html로 만들어
- 시안과 최대한 똑같이, 모바일 폭 기준
```

이어서 입력한다.

```
compare 폴더의 a.html, b.html 모두 첫 메모의 미리보기를 세 줄이 넘게 길게 바꿔줘
```

**확인 포인트**: 두 파일을 브라우저로 열어 개발자 도구 기기 모드로 폭을 바꿔 보고, 긴 미리보기가 어떻게 보이는지 비교한다. 수업에서 본 실험처럼 긴 미리보기와 색 이름이 갈리는지 본다. 결과는 모델과 실행마다 조금씩 다를 수 있다.
